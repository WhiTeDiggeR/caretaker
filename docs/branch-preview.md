# Быстрый просмотр ветки

Одна ссылка или одна команда — и свежая версия нужной ветки открыта в Godot 4.7 (issue #175). Ветка скачивается с GitHub, даже если её ещё нет на компьютере.

## Как это устроено

- Для просмотра есть **отдельная рабочая копия** — git worktree рядом с основным клоном: если клон лежит в `C:\Projects\caretaker`, копия будет в `C:\Projects\caretaker-review`. Она создаётся при первом запуске.
- **Основной клон не трогается:** его ветка, файлы и незакоммиченные правки остаются как есть. Обновляются только ссылки `origin/*` (как после обычного `git fetch`).
- Копия просмотра одноразовая: **в ней не работают и из неё не коммитят.** При каждом переключении она сбрасывается на `origin/<ветка>`, неотслеживаемые файлы удаляются.
- Папка `.godot/` (кэш импорта) сохраняется между ветками, поэтому повторное открытие не ждёт полный импорт (первый — около 4 минут).
- Файлы, которые Godot создаёт или переписывает при открытии (`*.import`, `*.uid`, `.godot/`, сцены `*.tscn`/`*.tres`, пересохранённые без настоящих изменений), следующему переключению не мешают.
- Если в копии просмотра есть другие изменения (кто-то всё-таки правил файлы), скрипт покажет список и спросит, сбрасывать ли их. Если Godot открыт на копии просмотра, скрипт предложит его закрыть.

Сцена считается «только пересохранённой», если после удаления атрибутов, которые Godot пересчитывает сам (`uid="uid://…"`, `unique_id=…`, `load_steps=…`, `format=…`), и пустых строк её текст совпадает с версией в ветке. Любое другое отличие считается ручной правкой.

## Установка (один раз)

Нужны: Git для Windows с Git LFS (`git lfs install` уже выполнен, см. [LFS.md](LFS.md)) и Godot 4.7.

1. Укажите Godot. Удобнее всего — переменная окружения пользователя `GODOT_BIN` с путём к **консольной** обёртке, имя файла не меняйте:
   ```powershell
   [Environment]::SetEnvironmentVariable("GODOT_BIN", "C:\Tools\Godot\Godot_v4.7-stable_win64_console.exe", "User")
   ```
   Другой вариант — папка с `godot` в `PATH`.
2. Зарегистрируйте ссылки `caretaker://` (права администратора не нужны). В PowerShell из основного клона:
   ```powershell
   powershell -ExecutionPolicy Bypass -File tools\dev\install_branch_protocol.ps1
   ```
   Скрипт копирует `open_branch.ps1` в `%LOCALAPPDATA%\Caretaker\` и запоминает путь к основному клону. После обновления `tools\dev\open_branch.ps1` запустите установку ещё раз.
3. Проверка: `Win+R` → `caretaker://open/team/integration` → Enter.

## Использование

- **Ссылка из сообщения агента:** `caretaker://open/<ветка>`, например `caretaker://open/task/174-door-feedback`. Откроется окно PowerShell с ходом работы, затем Godot.
- **Если ссылка не кликается** (не все программы делают такие ссылки кликабельными) — скопируйте запасную команду из того же сообщения и выполните её в PowerShell из основного клона:
  ```powershell
  powershell -ExecutionPolicy Bypass -File tools\dev\open_branch.ps1 task/174-door-feedback
  ```
- **Без имени ветки** скрипт покажет 20 последних веток с GitHub (свежие сверху): введите номер или имя.

Параметры `open_branch.ps1`:

| Параметр | Что делает |
| --- | --- |
| `<ветка>` | имя ветки на origin (`task/174-door-feedback`; можно с префиксом `origin/`) |
| `-ReviewPath <папка>` | другая папка для копии просмотра |
| `-Force` | сбросить ручные правки в копии просмотра без вопроса |
| `-NoGodot` | только подготовить копию, Godot не запускать |

Имя ветки проверяется строго: только латиница, цифры и `. _ / -`, без `..`. Ссылка с любыми другими символами отклоняется и ничего не запускает.

## Удаление

```powershell
powershell -ExecutionPolicy Bypass -File tools\dev\install_branch_protocol.ps1 -Uninstall
git worktree remove --force ..\caretaker-review
```

Первая команда убирает протокол `caretaker://` и копию скрипта из `%LOCALAPPDATA%\Caretaker\`, вторая (из основного клона) — копию просмотра. Если папку копии удалили вручную, выполните `git worktree prune`.

## Проверка скрипта

Git-логика проверяется на временном репозитории без Godot: `pwsh -NoProfile -File tools/dev/tests/open_branch_test.ps1`. Тест входит в `tools/ci/run_checks.sh` и пропускается, если `pwsh` не установлен.
