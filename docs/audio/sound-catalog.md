# Каталог звуков

Состояние на 2026-10-12. Задача #135. Каталог: перечень звуков, которые нужны игре по канону `docs/world/` и сценам `docs/game_design/`, и откуда каждый брать. Аудиофайлов в `team/integration` пока нет: `scenes/facility_ambience.gd` и `objects/power/placeholder_tones.gd` генерируют синусоиды при запуске. Сгенерированные заглушки систем и каталог id `data/audio/sfx.json` добавляет #126; этот документ планирует их замену и остальную работу и не дублирует систему id.

Пробные образцы процедурной генерации и разбор вариантов — в разделе «Пробы» внизу.

## Обозначения

**Приоритет**

- **P0** — нужно для начала игры (сцены 0–12 `01-opening.md`), то есть для текущего вертикального среза.
- **P1** — первое погружение (сон Боузера, `03-first-dream.md`) и ближайшие системы (химический протокол).
- **P2** — позже: сон Херобрина, финал, меню, озвучка.

**Источник** (первый — рекомендуемый)

- **Б** — готовая библиотека: Sonniss GDC, Freesound CC0, Kenney.
- **З** — своя запись (фоли): телефон или портативный рекордер, подвал, гараж, лестничная клетка.
- **П** — процедурный синтез (Python/numpy офлайн или GDScript в рантайме).
- **ИИ** — генеративная модель (ElevenLabs SFX, Stable Audio Open Small, Adobe Firefly).
- **М** — композитор или музыкальная библиотека.
- **Г** — голос: актёр или синтез речи.

«Вар.» — сколько вариаций нужно, чтобы не было слышно повтора (для `AudioStreamRandomizer`).

### Своя запись

Самый дешёвый способ получить звук, которого нет в библиотеках и который будет звучать «своим». Хватит телефона с внешним микрофоном или рекордера уровня Zoom H1n. Хорошие места — подвал, паркинг, лестничная клетка: там уже есть нужная бетонная акустика. Там же можно записать импульсную характеристику (хлопок или лопнувший шарик) и использовать её как реверберацию зон.

Подходит для A01–A09, B01–B02, B04, C03–C05, C07, C10, D01–D02, E05.

### Генерация

| Способ | Хорошо | Плохо | Лицензия |
|---|---|---|---|
| Процедурный синтез (как в пробах) | гудение, трансформаторы, тревоги, интерфейс, терминал, искры, газ, дроны, кристалл, врата, звуки сна; бесконечные вариации и точная длина петли | шаги, ткань, бумага, голос, существа, реалистичная вода; сложные механические последовательности звучат «синтетически» | своя |
| ElevenLabs Sound Effects | короткие одиночные звуки по текстовому описанию, существа, удары, стингеры | точная синхронизация, длинные бесшовные петли, единообразие набора вариаций | коммерческое использование только на платном тарифе |
| Stable Audio Open Small (локально, работает на CPU) | текстуры, окружение, слои для сна | одиночные удары и точные механизмы | Stability Community License: бесплатно до $1M годового дохода |
| Adobe Firefly (звуковые эффекты) | синхронизированные по времени эффекты | — | платный тариф |
| Meta AudioGen | — | — | веса CC-BY-NC, **не подходит** |

ИИ-звук почти всегда нужно дорабатывать: обрезать, выровнять громкость, подогнать петлю и пропустить через общую реверберацию зоны. Условия лицензий меняются: перед использованием проверить их на сайте сервиса и записать в манифест.

## Рекомендуемый подход

Гибрид по типу звука:

1. **Библиотеки (Sonniss, Freesound CC0)** — основа для дверей, механизмов, генератора, окружения, шагов. Это самый большой объём и самый высокий уровень качества.
2. **Своя запись** — фоли (бумага, ключи, одежда, ручки дверей) и импульсные характеристики подземных помещений.
3. **Процедурный синтез** — всё электрическое и интерфейсное: гудение, лампы, искры, тревоги, терминалы, мониторы, кристалл, врата, печать. Хранить генератор в `tools/audio/`, чтобы звуки можно было пересобрать с другими параметрами.
4. **ИИ** — там, где нет записи и синтез не справляется: существа (дыхание Боузера, стражи), звуки сна, одиночные необычные события. Бюджета на платные сервисы нет, поэтому только бесплатные варианты с коммерческой лицензией (Stable Audio Open Small локально).
5. **Музыка** — из библиотек (см. решения ниже). Голоса пока не делаем.

Единство звучания: все источники проходят одну цепочку (выравнивание громкости, эквализация, одна система реверберации по зонам в Godot), иначе библиотечные, синтезированные и ИИ-звуки будут звучать как из разных игр.

### Техническая сторона в Godot

- Шины: `Master` → `Music`, `SFX`, `Ambience`, `UI`, `Voice`; на `SFX` и `Ambience` — отправка в шины реверберации зон (`Reverb_Small`, `Reverb_Concrete`, `Reverb_Hall`, `Reverb_Dream`). Шина `Ambience` уже ожидается в `facility_ambience.gd`.
- Формат: короткие одиночные звуки — WAV 44,1 кГц 16 бит (без задержки декодирования), петли и музыка — OGG Vorbis.
- Вариации — `AudioStreamRandomizer` (случайный выбор, разброс высоты ±5 %, громкости ±2 дБ).
- Одиночные звуки окружения — отдельный скрипт-эмиттер, а не сотни `AudioStreamPlayer3D` в сцене.
- `PlaceholderTones` и `facility_ambience.gd` заменяются на файлы постепенно, по одному звуку; экспортируемые поля `SectionSound` уже позволяют это сделать без кода.
- Происхождение каждого файла (источник, автор, лицензия, правки) записывается в манифест по образцу `tools/props/manifest.json`.

## Хранение исходников библиотек

Лицензия Sonniss запрещает распространять звуки отдельными файлами, а репозиторий публичный. Сырые паки ещё и большие: десятки гигабайт, в Git их держать нельзя в любом случае. Варианты:

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| А. Только CC0 и свои звуки в репозитории | Sonniss не используем. Берём Freesound CC0, Kenney, свою запись, синтез | юридически чисто, ничего не меняется в процессе | больше ручной работы, ниже качество механики и окружения |
| Б. Сырьё вне Git, в репозиторий только готовые игровые звуки | паки на общем облачном диске; в Git — смикшированные и обработанные файлы | просто, бесплатно | серая зона: обработанный звук из Sonniss в публичном репозитории всё равно можно скачать отдельно |
| В. Приватный репозиторий-подмодуль для аудио | `caretaker-audio` (приватный) подключается как подмодуль в `audio/`; сырьё всё равно на облачном диске | чисто по лицензии, публичный репозиторий остаётся открытым | доступ к подмодулю нужен каждому участнику, CI и агентам; без него игра запускается без звука (нужны заглушки) |
| Г. Сделать основной репозиторий приватным | сменить видимость `WhiTeDiggeR/caretaker` | проблема исчезает целиком | проект перестаёт быть открытым; лимиты GitHub Actions для приватных репозиториев |

Git LFS сам по себе проблему не решает: файлы LFS в публичном репозитории тоже публичны. LFS помогает только с размером.

Выбран вариант **В** (#136). Пока подмодуля нет, работаем по варианту **А**: в публичный репозиторий попадают только CC0, свои записи и синтез. В любом варианте сырые паки лежат вне Git, а происхождение каждого файла записывается в манифест.
