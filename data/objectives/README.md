# Цепочки целей

Файлы `*.json` этого каталога читает автозагрузка `Objectives` (`objects/objectives/objectives.gd`).

```json
{
  "chains": {
    "<id цепочки>": {
      "final_text": "Текст цели после последнего шага (пусто — цель скрывается)",
      "next": "<id цепочки, которая стартует после этой (необязательно)>",
      "steps": [
        {"id": "<id шага>", "text": "Текст на экране", "done_when": {<условие StateRules>}}
      ]
    }
  }
}
```

- Цепочку запускает сценарий: `Objectives.start(&"opening")`. Активный шаг попадает в `GameState.set_objective`.
- `done_when` — условие в формате `data/terminals/README.md` («Условия»): `flag`, `not_flag`, `access`, `power`, `all`, `any`. Если условие уже выполнено, шаг пропускается сразу.
- `next` — законченная цепочка сама запускает следующую (`opening` → `part2`); так же и после загрузки сохранения, где цепочка уже закончена.
- Прогресс сохраняется вместе с игрой (`GameState` → `objectives`).

## Флаги цепочки `opening`

Часть флагов уже ставят системы: `opening/hero_capsule_open` (капсула героя), `generator_started` (процедура генератора), `senior_key_taken` (ключ старшего), `caretaker_assigned` (протокол преемственности), `module4_ready` (чек-лист поста), `dream/returned/module_4` (выход из сна модуля 4). Флаги переходов между зонами — `opening/left_emergency_block`, `opening/reached_old_core`, `opening/reached_old_control`, `opening/reached_module_4` — ставят зоны-триггеры, когда начало будет собрано в сцене комплекса (пролог). Формулировки целей — тестовые.

## Цепочка `part2` и флаги прогресса части 2

Канон — `docs/game_design/08-part2.md` (#226). `part2` стартует сама, когда закончена `opening` (выход из первого сна, `dream/returned/module_4`). Шаги: вернуться к пульту старого ЦУ → «Восстановить системы» (три направления в любом порядке) → проверить состояние модулей (финал части). Пульт старого ЦУ (`data/terminals/opening_old_cp.json`, экран `recovery_map`) показывает карту восстановления и отмечает законченные направления `[+]`. Формулировки — тестовые.

Список флагов части 2 фиксирован; на них опираются задачи части, межсонье (#228) и монитор. Все флаги логические, ставятся один раз и не снимаются (кроме `part2/n2_trust`).

| Флаг | Что значит | Кто ставит |
|---|---|---|
| `part2/recovery_map` | Смотритель открыл карту восстановления (П2) | Пульт старого ЦУ, экран `recovery_map` |
| `part2/dir_lower_done` | Направление «Нижний контур» закрыто (П3а) | Задача «Нижний контур» |
| `part2/dir_upper_done` | Направление «Верх» закрыто (П3б) | Задача «Верх» |
| `part2/dir_storage_done` | Направление «Склад» закрыто (П3в) | Задача «Склад» |
| `part2/rule_3_4` | Прочитан регламент «Одновременное снижение стабильности объектов 3 и 4 недопустимо»; один флаг на оба места — пост №2 и монитор нового ЦУ: где прочитан первым, там и показан, второе место его пропускает | Монитор нового ЦУ (`data/terminals/part2_new_cp.json`), пост №2 |
| `part2/n2_first_text` | Получен первый текст №2 «МОДУЛЬ 4. ОХЛАЖДЕНИЕ. ЧАС.» — запускает кризис модуля №4 (П4) | Текстовый канал №2 |
| `part2/module4_cooling_leak` | Первый текст №2 получен, давление охлаждения модуля №4 падает (П4) | Кризис модуля №4 (`Cooling`) |
| `part2/module4_overheat` | Перегрев треснул печать сна модуля №4 — открывает сон Боузера V2 (#234); ставится при любом исходе кризиса | Кризис модуля №4 (`Cooling`) |
| `part2/module4_crisis_resolved` | Кризис модуля №4 закончен: аварийный ремонт охлаждения и сухой тест протокола, с химпротоколом или без (П4–П5); настройка по схеме из сна V2 — отдельный флаг задачи сна | Кризис модуля №4 (`Cooling`) |
| `part2/v2_done` | Печать Горна восстановлена, герой вышел из сна V2 (П6) | Сон Боузера V2 |
| `part2/n2_reply` | Состоялся ответ №2 на посту (П7) | Текстовый канал №2 |
| `part2/finale` | Финал части: модуль №3 теряет стабильность, доступ выдан (П9) | Финал части 2 |
| `part2/dream_trace_2` | Герой увидел табличку «2» в межсонье (первый выход через врата); табличка записана в журнал | Межсонье (#228) |
| `part2/n2_believed` | Герой поверил предупреждению №2, кризиса не было — межсонье показывает табличку с затянутой трещиной | Кризис модуля №4 (`Cooling`) |
| `part2/chem_protocol_fired` | Герой медлил, сработал химпротокол — межсонье показывает табличку, отвёрнутую к стене | Кризис модуля №4 (`Cooling`) |
| `part2/n2_trust` | Доверие к №2, число (`GameState.set_flag(flag, value)`); условиями StateRules не сравнивается | Решение «поверить / проверить», порядок направлений |

Межсонье (#228) бывает при каждом выходе из сна, включая первый, и выбирает отголоски условиями StateRules по этим флагам: например, первый выход — `{"not_flag": "part2/recovery_map"}`, после первого текста №2 — `{"flag": "part2/n2_first_text"}`. Флаг `dream/returned/<модуль>` ставится в момент выхода и для выбора отголоска не подходит: он истинен уже при первом выходе. Флаги показанных отголосков межсонье заводит само: `interdream/shown/<отголосок>`. Отголоски и их условия — `data/dreams/interdream.json` (формат — `docs/game_design/10-interdream.md`, раздел 7).

## Направление «Склад» (#231)

Набор `objects/storage/storage_kit.tscn` — мастерская и склад техуровня: баллон реагента (`item_reagent_cylinder`, +1 заряд в запас `Containment`), сервисный ключ техгалерей (`item_gallery_tool`: процедуры обслуживания модуля — `Containment.service_seconds`, пока вентиляция, — вдвое короче, `data/containment/modules.json` → `service`) и журнал склада (`storage_log`, ставит `part2/storage_log_read`). Когда взяты оба предмета и прочитан журнал, событие `part2_storage_done` ставит `part2/dir_storage_done`. Запас реагента в начале игры — 0: единственный запасной заряд — этот баллон; перезарядка модуля помечает его израсходованным (`item_reagent_cylinder/used`). Пока набор стоит на полигоне (момент отладки «Часть 2: склад техуровня»); в комплексе его место — мастерская и склад сектора техуровня (`T-WORKSHOP/workshop`, `T-WORKSHOP/parts_store`) после перегенерации.

## Направление «Верх» (#235)

Восточная и западная подстанции поздних секторов — процедуры `data/procedures/part2_upper_east.json` и `part2_upper_west.json` (журнал защиты ставит `part2/upper_east_diagnosed` / `part2/upper_west_diagnosed`); каждая даёт основное питание своей секции — `late_east`, `late_west`, — и на этих секциях стоят двери коротких путей. Серверная нового ЦУ (`part2_new_cp_servers.json`) запускается, когда готовы обе подстанции, и питает секцию `new_cp`. Монитор нового ЦУ (`data/terminals/part2_new_cp.json`, секция `new_cp`) после сводки ставит `part2/dir_upper_done` и, если `part2/rule_3_4` ещё нет, показывает регламент 3+4. Процедуры не ведут цель (`drive_objective = false`), цель части 2 остаётся «Восстановить системы». Остальная часть ЦУ закрыта (заклинившая дверь, завал, нет питания). Пока всё собрано на полигоне (станция `UpperStation`, моменты отладки «Часть 2: «Верх» первым» и «…после поста №2»); расстановка в комплексе — после его перегенерации.

## Направление «Нижний контур» (#229)

Переиспользуемые сцены `objects/lower_contour/`: подстанция нижнего контура (`lower_substation.tscn`, процедура `data/procedures/part2_lower_substation.json`: журнал защиты `part2/lower_diagnosed` → снять заземление и включить разъединитель → подача напряжения → контроль изоляции) даёт основное питание секции `lower_main` — пассажирской магистрали нижнего этажа; на ней стоят дверь магистрали и короткий путь. Ранняя лаборатория сна (`early_lab.tscn`: наблюдательная, опечатанное кресло синхронизации, датчики, экраны в помехах, документ `part2_memory_sync_closed`) и пост камеры №2 (`post_2.tscn`: капсула за стеклом в помехах, закрытая дверь камеры с табличкой «2», регламент `part2_rule_3_4` ставит `part2/rule_3_4`, терминал канала №2 — см. ниже). Вход в лабораторию и в пост ставит `part2/lower_lab_reached` и `part2/lower_post_reached`; вместе с готовой подстанцией это закрывает направление — событие `part2_lower_done` ставит `part2/dir_lower_done`. Первый текст №2 ставит канал (ниже).

Старые таблички второй очереди (`old_plate.tscn`, шрифт `screen_mono_old`) — тот же шрифт, что у таблички «2» в межсонье: после следа `part2/dream_trace_2` осмотр таблички узнаёт шрифт, ставит `part2/plate_compared` и указывает на камеру 2 вдоль магистрали за лабораторией. Пост этим не запирается — след можно пропустить, проход к посту не зависит от межсонья. Пока всё на полигоне (станция `LowerStation`, моменты отладки «Часть 2: «Нижний контур» первым» и «…после «Верха»»); расстановка в комплексе — после его перегенерации: подстанция — техуровень, лаборатория — `L-SLEEP-LAB`, пост — `L-CHAMBER-2`.

## Канал №2 на посту камеры 2 (#230)

Терминал поста (`post_2.tscn` → `Terminal`, секция `lower_main`, эпоха `old_core`) — программа `data/terminals/part2_post2.json`, все тексты в ней. До ремонта — образы: капсула, табличка «2», схема узла связи с крестом; самодиагностика узла указывает на плату в ЗИП ранней лаборатории. Плата связи — предмет `item_n2_link_part` (`data/items/part2_post2.json`, лежит на столе лаборатории `early_lab.tscn` → `LinkPart`); установка с терминала ставит `part2/n2_link_installed` (плата пропадает из «При себе»). Затем первый текст «МОДУЛЬ 4. ОХЛАЖДЕНИЕ. ЧАС.» ставит `part2/n2_first_text` один раз — когда текст допечатан. После `part2/module4_crisis_resolved` — ответ №2: первая строка зависит от `part2/n2_believed` (поверил ли герой), «Кто ты?» → «Объект 2. Камера повреждена. Мне нужен оператор.» ставит `part2/n2_reply`. О себе №2 не отвечает. Всё состояние канала — флаги, поэтому сохраняется с игрой. Числовое `part2/n2_trust` условиями не сравнивается, канал опирается на `part2/n2_believed`. Тексты №2 черновые — на согласовании у автора. Момент отладки «Часть 2: ответ №2 на посту».

## Кризис модуля №4 (#232)

Автозагрузка `Cooling` (`objects/containment/module_cooling.gd`, параметры — `data/containment/modules.json` → `cooling`, числа тестовые). Первый текст №2 (`part2/n2_first_text`) запускает утечку: давление охлаждения модуля №4 падает `grace_seconds` (5 мин), прогноза ещё нет; пост модуля (`data/terminals/opening_module4_post.json`, строка `{cooling_status}`) и манометр техгалереи показывают давление. Цель не меняется — поверить №2 или нет, решает игрок.

- **Поверил:** ремонт до перегрева — `part2/n2_believed`, `part2/n2_trust` +1; перегрев всё же треснул печать: нестабильность +10 (длинный прогноз), `part2/module4_overheat`.
- **Медлил:** утечка истекла — перегрев: нестабильность +30 (прогноз появляется сразу) и ускоренный рост (+12 %/мин) до ремонта; истечение прогноза — химпротокол с окном ремонта (`Containment`), `part2/chem_protocol_fired`, реагент модуля №4 израсходован. Пополнение — вентиляция и баллон со склада на панели реагента.
- **Ремонт** — процедура `data/procedures/part2_module4_cooling.json` в техгалерее (`objects/containment/cooling_gallery.tscn`): отсечь повреждённую ветку → открыть подпитку → удержать насос; сервисный ключ склада вдвое укорачивает удержания. После ремонта при любом выборе — учебный сухой тест «Проверка герметизации… норма» без расхода реагента, затем `part2/module4_crisis_resolved`.

Пока техгалерея и пост стоят на полигоне (станция `Module4Station`, момент отладки «Часть 2: кризис модуля №4 — давление падает»; F10 ускоряет время); в комплексе — после его перегенерации.
