# Скриптовые события

Режиссура без нового кода в сцене (#133): **триггер** запускает **последовательность** шагов.
Шаги описаны здесь, в `data/events/*.json`; в сцене стоят только узлы.

## Узлы

- `EventSequence` (`objects/events/event_sequence.gd`) — исполнитель события.
  - `event_id` — id события из этого каталога.
  - `targets` — объекты сцены, которые шаги называют по имени: имя → путь к узлу (двери, точки звука). Пути разрешаются один раз в `_ready()`.
  - `repeatable` — можно запускать повторно; по умолчанию событие однократное.
  - `play()` — запустить; `cancel()` — остановить. Сигналы `started`, `step_started`, `finished`.
- `EventTrigger` (`objects/events/event_trigger.gd`, `Area3D`) — что запускает последовательность (`sequence`).
  - `AREA` — игрок вошёл в зону (форма — дочерний `CollisionShape3D`).
  - `CONDITION` — условие `StateRules` в `condition_json` стало истинным. Проверяется при изменениях `GameState`, а не каждый кадр.
  - `CALL` — из кода или по сигналу другого узла: `fire()`.

## Однократность и сохранения

- Законченное событие ставит флаг `event/done/<id>`. Флаг сохраняется вместе с игрой, поэтому однократное событие больше не срабатывает, в том числе после загрузки.
- Загрузка сохранения останавливает идущие события. Незаконченное событие может сработать снова: его флаг ещё не поставлен.
- Состояние, которое меняют шаги, сохраняют сами системы: питание и флаги — `GameState`, двери (открыта или закрыта, аварийная блокировка) — группа `persist`.

## Формат

```json
{
  "events": {
    "<id>": {
      "steps": [ { "<действие>": … }, … ]
    }
  }
}
```

В каждом шаге ровно одно действие. Шаги идут по порядку; следующий начинается, когда закончен предыдущий.

| Действие | Пример | Что делает |
|---|---|---|
| `wait` | `{"wait": 1.5}` | Пауза в секундах. |
| `power` | `{"power": {"section": "lab", "power": "emergency", "flicker": 4}}` | Питание секции: `off`, `emergency` или `main`. Свет, двери и звук секции следуют за питанием. `flicker` — сколько раз мигнуть перед итоговым состоянием. |
| `door` | `{"door": {"target": "lab_door", "action": "lock"}}` | Действие над дверью из `targets`. `open` и `close` работают в обход замков; `lock` и `unlock` ставят и снимают аварийную блокировку. |
| `sound` | `{"sound": "alarm_stage", "at": "lab_door"}` | Звук из каталога `Sfx` (#126); `at` — точка из `targets`, без неё звук неположенный. Пока в проекте нет `Sfx`, шаг ничего не делает. |
| `message` | `{"message": {"title": "АВАРИЯ", "text": "…"}}` | Сообщение на экране. |
| `hint` | `{"hint": "crawl"}` | Подсказка из `data/hints`. Однократна, как и все подсказки. |
| `objective` | `{"objective": "sandbox_alarm"}` | Запустить цепочку целей из `data/objectives`. |
| `effects` | `{"effects": [{"set_flag": "lab/alarm"}]}` | Действия `StateRules` (`data/terminals/README.md`, «Действия»): флаги, допуски, цель одной строкой, питание. |
| `shake` | `{"shake": {"strength": 0.06, "seconds": 0.8}}` | Тряска камеры, затухает к концу. |
| `run` | `{"run": "other_event", "await": true}` | Запустить другое событие сцены. С `await` — дождаться его конца. |

Каталог проверяется тестами (`EventLibrary.errors()`): неизвестное действие, лишнее действие в шаге, неверная дверь или уровень питания — ошибка.

## Пример: авария на полигоне

`sandbox_blackout` в `sandbox.json`, станция `scenes/sandbox/stations/event_station.tscn`. Игрок входит в зону, и происходит следующее:

1. Свет секции мигает и гаснет до аварийного.
2. Звучит тревога, камеру трясёт.
3. Дверь закрывается и блокируется.
4. На экране появляется сообщение, ставится цель.

Кнопка на станции снимает аварию: питание возвращается, блокировка снимается. Это отдельное, повторяемое событие `sandbox_blackout_reset`.
